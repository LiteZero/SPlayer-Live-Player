# 歌词首轮对接

状态（2026-11-11）：已交付可导入插件、回环服务、诊断设置页和透明歌词输出。用户已确认首版能运行；本次新增换行动画、可选音译和翻译、自定义 CSS，并通过模拟宿主与 Edge 验证。对应 R-01、R-02、R-04 至 R-07，以及 P-01 至 P-07 的首轮实现。

## 启动

在仓库根目录执行（Node.js ≥ 22.12，使用 npm 锁文件）：

```sh
npm ci
npm run build
npm start
```

1. 在 SPlayer-Next 中打开 **设置 → 插件管理 → 本地导入**，选择 `dist/splayer-live-lyrics.js`。启用插件并保留 `network` 和 `control` 权限。插件最低要求 API 4，真机验收优先使用 SPlayer-Next 1.2.0 / API 5。
2. 打开 [本地设置](http://127.0.0.1:19633/)。播放一首歌，确认状态为「歌词已就绪」，预览有歌词。
3. 在 OBS 新建浏览器源，粘贴 [歌词输出地址](http://127.0.0.1:19633/obs)。可先用 1200 × 180，把它放在一个有颜色的源上方。音频继续由 OBS 单独采集。

## 自定义歌词样式

歌词上方会显示当前歌曲的封面、歌名和歌手；播放时圆形封面旋转，暂停时停在原角度。没有可用封面时显示唱片占位，无歌词的曲目也可以显示歌曲信息。封面由采集插件 0.2.0 提供；重新导入新版脚本并重启后端后，刷新 OBS 浏览器源即可使用。宿主私有封面地址不可用于浏览器，会显示占位。

默认换行时，旧词上移淡出，新词下移淡入。当前歌词有音译或翻译时，按原文、音译、翻译的顺序展示；没有内容的副行不占位置。每一行按当前可用宽度独立布局：放得下时居中，放不下时从头滚到尾。调整浏览器源宽度或字体后会重新测量。系统启用减少动态效果时，长行改用换行显示。

在设置页的「OBS 浏览器源 → 自定义 CSS」粘贴样式，点击「保存并应用」。设置预览与已连接的 OBS 输出同步更新，服务重启后仍保留样式。点击「清空样式」再保存即可恢复默认。

```css
.lyric-original { color: #ffe0a8; font-size: 48px; }
.lyric-roman { color: #cbd5e1; font-size: 24px; }
.lyric-translation { color: white; font-size: 28px; }
.renderer-slot {
  --lyric-travel: 0.6em;
  --lyric-in-duration: 320ms;
  --lyric-out-duration: 240ms;
}
```

整组歌词可以通过 `.lyric-block` 调整行距或样式；歌曲信息栏可通过 `.now-playing`、`.now-playing-disc`、`.now-playing-title` 和 `.now-playing-artist` 调整。CSS 仅作用于输出页，保存在仓库根目录的 `obs-custom.css.local`，不纳入 Git。字体可指定本机已安装的字体。

## 模拟与诊断

默认端口 `19633` 在开始开发前已成功绑定验证。若被占用，在 PowerShell 用 `$env:SPLAYER_LIVE_PORT = "19634"; npm start`，并把插件的「本地歌词后端」和 OBS 地址改为对应端口。关闭后端用 Ctrl+C。初次未启动服务时，浏览器直接报告连接失败；已加载的设置页会显示「后端未启动或连接已中断」。

没有 SPlayer 时，构建并启动后端后，可在另一终端运行 `npm run demo`。它用模拟宿主执行同一个编译后的插件。输入 `a`、`b`、`empty` 切歌，`p` 暂停或继续，`seek 4500` 跳转，`offset 500` 修改歌词偏移，`q` 退出。模拟器会占用唯一的插件会话，真机验收前请退出。自定义端口可用 `npm run demo -- http://127.0.0.1:19634`。

## 协议 v1

| 边界 | 实现 |
| --- | --- |
| 插件入站 | `POST /api/plugin/session` 声明版本、会话 ID、启动时间、宿主版本与 API 级别；更新的会话接管。服务启动 ID（`serverId`）随重启变化。两个插件端点使用 JSON 和 `X-SPlayer-Live-Protocol: 1`。 |
| 文档与播放样本 | `POST /api/plugin/push` 按会话递增 `seq`，含 `serverId` 和曲目／歌词修订。文档更新才附带曲目与完整歌词，普通样本只有播放锚点及可选诊断。拒绝旧会话、旧序号和旧修订；过期返回 `snapshot_required`，服务重启返回 `session_required`，插件重新协商并重送全文。 |
| 浏览器分发 | 同源 `/ws` 只读。首连收到 `snapshot`，随后收到带连续序号的 `update`；进度更新不带文档。自定义 CSS 使用独立样式修订，保存后通知输出页重新加载。检测序号缺口、启动 ID 变化或未知修订时关闭连接并重取快照。隐藏或离开输出页会断开连接，重新可见后重新同步。 |
| 设置诊断 | `GET /api/status` 区分等待插件、宿主断连、无曲目、待确认歌词、无歌词和歌词已就绪。最近事件上限 120 条，可导出 JSON，包含曲目标识、时间、行数、播放位置和偏移，不含歌词正文。 |

曲目标识由来源和 ID 组成。共享文档保留毫秒行／字时间、翻译、音译、背景行和对唱标记，以及宿主提供的语言、注音等可选字段。普通采样周期初定 400 ms，宿主事件可提前触发采样；最多一个请求在途，失败后退避。上传上限 2 MiB 是本服务限制，实际宿主上限待验证。连续 3 秒无新样本清空输出；停止时留空，暂停时保留当前行。

插件把宿主的墙钟采样戳转换为有上限的相对年龄；后端计算样本在服务中停留的时间；浏览器以自身单调时钟在接收后推进。首轮按回环传输处理，没有另外估算下行延迟。播放时间加一次宿主歌词偏移，正值让歌词提前。轻量渲染器只在歌词行改变时更新文本，由公共层调度下一行；其他渲染器可以通过注册表延迟加载并使用相同的文档和时钟。

## 歌词归属依据

核对了 SPlayer-Next `v1.2.0`（提交 `9d3ca78f107b7cbe28b1ef7ce9041de9bad55531`）的 `electron/main/services/nowPlaying.ts` 和 `electron/main/plugins/playbackBridge.ts`：初次补发先发曲目，再发歌词；正常切歌更新同一份快照后，先发曲目，再发歌词。插件依赖该顺序，把候选歌词限制在当前曲目事件之后，再核对 `getNowPlaying()` 的来源、ID、歌词可用性及行数；查询期间遇到新曲目或歌词事件时，丢弃该次查询。

`lyricChange` 本身没有曲目 ID，行数相同也不能证明归属。如果其他宿主版本改变事件顺序，或宿主先把旧词提交给新曲，需要先检查事件记录；本轮不将模拟测试当作真实快速切歌的验收证据。无歌词状态基于宿主报告及切歌后的短暂等待；慢歌词加载仍可能先显示无歌词，随后自动转为就绪。

| SPlayer-Next / OBS 真机 | 用户已确认首版能运行；本次展示改动尚未在 OBS 中复测，实际透明合成和渲染开销待测。 |

真机联调建议按以下顺序，并从设置页保存事件诊断：

1. 在播放中导入并启用插件，记录播放器版本、API 级别、测试歌曲和歌词类型。核对是否收到初始 `trackChange → lyricChange`，以及预览是否跟上当前播放行。
2. 暂停、继续、前后拖动，再分别设正负歌词偏移。在 OBS 比较同一歌词行的出现时刻，记录偏差和方向。
3. 在歌词已加载的两首歌间快速来回切换，再切到无歌词或歌词加载较慢的歌曲。确认歌词不会串入上一首，并记录事件序号、行数和曲目标识。
4. 刷新浏览器源、隐藏再恢复场景、禁用再启用插件、关闭再启动后端。确认失联时输出留空，恢复后回到当前歌词。
5. 在 OBS 用彩色底图确认透明度和文字边界，记录 OBS 版本、尺寸与帧率。AMLL 与真实性能对比进入后续阶段。
