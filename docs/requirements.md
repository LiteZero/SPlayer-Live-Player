# 需求与验收

状态：核心产品方向已确认，样式与量化指标待定。日期：2026-11-11。

## 产品目标

为直播用户提供 SPlayer-Next 插件及配套前后端应用：插件采集歌词和播放状态，经后端传给网页，
网页作为 OBS 等直播软件的浏览器源叠加到画面中。用户可选择不同展示方式，AMLL 是其中一种。
首版同机运行，后端在本地启动。

正式歌词应用仍处于准备阶段。后端到 SPlayer 的点歌专项已提供独立验证程序并实测通过。
当前只阅读 B 站接口资料，提出直播间到后端的可行方案，不实施或执行连接验证。

## 核心使用流程

1. 启动本地后端，将配套插件导入 SPlayer-Next。
2. 插件向后端传递当前歌曲、歌词和播放进度。
3. 选择歌词展示方式，把输出网页地址添加到 OBS 浏览器源并设置尺寸。
4. 在 SPlayer 播放、暂停、切歌或拖动进度，直播画面中的歌词同步更新。

启动方式、默认端口、设置页面和预设样式尚未实现。

## 已确认需求

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| R-01 | SPlayer 插件接入 | 可导入单个脚本，使用文档支持的接口采集歌词及状态 |
| R-02 | 前后端传递歌词 | 插件数据经过后端到达网页；网页刷新后取得完整当前快照 |
| R-03 | AMLL 作为可选展示方式 | 选择该模式时实际使用 AMLL 渲染，保留可用的逐字数据 |
| R-04 | OBS 浏览器源 | 使用网页 URL 加入 OBS 后可持续展示歌词 |
| R-05 | 首版同机部署 | 插件、后端、网页和 OBS 在同一电脑完成全流程 |
| R-06 | 多种方式可扩展和选择 | 先定义统一渲染接口与选择入口，其他渲染器可后续接入；本轮不要求实现全部模式 |
| R-07 | 性能与渲染方式解耦 | 仅加载和运行所选渲染器；轻量模式不依赖 AMLL 的初始化和动画循环 |
| R-08 | 长期弹幕点歌 | 未来收到「点歌 xxx」时搜索并播放所选音源返回的第一项；直播间到后端当前仅提出方案 |
| R-09 | 为更多指令预留扩展 | 后端命令保留类型、参数与结果边界，当前只验证 `requestSong` |
| R-10 | 本次验证后端到播放器 | 人工提交结构化请求，插件搜索并请求播放首项，查询真实状态确认；记录失败与未确认结果 |
| R-11 | B 站弹幕接入可行性 | 基于指定参考仓库提出可连接、解析和转发的候选流程及条件；当前不连接、不写接入代码、不触发点歌 |

R-10 已在 SPlayer-Next 1.2.0／API 5 上实测通过，详情见 [点歌与后端控制](song-requests.md)。
搜索第一项以音源返回顺序为准，不另行挑选原唱，第一项失败时不自动尝试后续项。

## 首版建议行为

以下是基于直播场景提出的默认值，尚未逐项确认。

| 编号 | 建议 | 验收条件 |
| --- | --- | --- |
| P-01 | 透明背景和干净输出 | OBS 下方彩色画面可透出，输出页不出现工具栏、调试文本或错误弹窗 |
| P-02 | 连续同步 | 播放时推进、暂停时冻结，恢复和 seek 后校准；同步误差目标另行确定 |
| P-03 | 全文与进度分开发送 | 普通进度更新不重复上传整首歌词，不重建整首渲染对象 |
| P-04 | 正确清理与恢复 | 切歌不串词；无歌词或停止时默认留空；暂停时保留当前歌词 |
| P-05 | 失联处理 | 不无限推算过期进度，输出页默认留空，独立诊断页报告原因；恢复后重新同步 |
| P-06 | 独立预览／设置页 | 主播可选择渲染器、预览样式并查看连接状态 |
| P-07 | 网页只输出歌词画面 | 音频继续由 SPlayer 和 OBS 的音频采集流程提供 |

## 待明确细节

- 除 AMLL 外，首个轻量展示方式是什么：单行字幕、双行字幕、简单多行等仅为候选。
- 默认渲染器、能否在直播中切换，以及切换失败时的处理方式。
- 标题、歌手、封面、翻译和音译的展示范围；字体、颜色、对齐和边距设置。
- 浏览器源尺寸、帧率、同步误差目标及手动同步偏移需求。
- 后端启动与分发形式；是否期望仅导入插件便启动整套应用。
- 真实联调用的 SPlayer／OBS 版本及逐字歌词测试歌曲。

## 验收场景

1. SPlayer 已经播放时启用插件，OBS 新建或刷新浏览器源仍显示当前歌词。
2. 逐行和逐字歌词均有对应展示；缺少逐字时间时不伪造逐字高亮。
3. 暂停、恢复、前后跳转和快速切歌均正确，歌词迟到时不串入上一首。
4. 无歌词、插件禁用和后端重启按策略清理，恢复后拿到完整状态。
5. OBS 隐藏场景后恢复或刷新源，重新校准进度。
6. 选择其他渲染器时不加载 AMLL 代码与专有样式；切换后旧实例释放资源。
7. 在选定尺寸下确认透明背景、文字边界和持续渲染表现。

长期需求包括弹幕点歌及更多指令；后端到播放器已独立验证，直播间输入目前只有 [可行性方案](bilibili-ingress.md)。
音视频直播解码、云端部署和多用户房间不在当前范围。
