# 首版构建与交付

## v0.2.0 后端点歌队列（2026-11-12）

应用 v0.2.0 / 插件 0.4.0 按用户新方案维护后端 FIFO，每次只将一首放到 SPlayer“下一首”，确认实际开始播放后再安排后续点歌。设置页显示当前点歌、待播及排队记录，并可在核对后手动解除待播等待。保留 WSS 节点 / 443 回退。

针对「入队结果不确定」，检查本机安装的 SPlayer 实现确认：`addToQueue` 只回报提交数量，渲染层会跳过列表已有 ID。旧插件一律要求队长加一，因此重复点歌被误判。新版完整分页检查已有曲目，明确回报“已在播放列表”并继续；新曲按整体计数及下一首位置核对，兼容其他歌曲重排。当前文档化接口无法把已有歌曲移动到下一首，故明确跳过，不宣称能重新安排它。

39 项测试和 Edge 设置页验证通过。覆盖连续三首的单首预放、暂停与无关切歌、469 首随机列表、已有曲目、错误位置、截断分页、回报丢失、旧版本握手、失联及解除等待。真实房间连续点歌仍需人工验收。交付包为 `SPlayer-Live-Player-v0.2.0-win-x64.zip`。

升级需停止旧后端、启动新版并重新导入 0.4.0 插件；B 站内存登录和点歌设置需重新建立。开发时不重启已有登录服务，不导出凭据，构建包不含账号数据。保留旧版 ZIP。

v0.2.0 实际 ZIP 的独立解压检查通过：校验压缩包及 56 个文件，在中文 / 空格路径使用内置 Node 启动，验证模拟扫码、实际构建插件的单首预放及播放采样推进、OBS、外观配置写入与重复启动复用。ZIP SHA256 为 `5468a043ce5c0169d40b772fcc47295e940f673c1c21336f49d4fcaa85123238`。

## v0.1.1 修订（2026-11-12）

修复用户连接直播间时停在「正在建立 WSS 连接」的问题：此前只选择平台返回的首个节点及端口，当前环境该节点的 2245 端口超时；同一主机 443 端口可以完成 WSS 和直播认证。

现保留最多三个平台返回的合法节点，按返回端口及标准 443 端口生成去重后的有限候选。每次建连独立限制为 6 秒，认证回复限制为 8 秒；握手网络失败、HTTP 拒绝或等待超时会尝试下一个候选。全部失败后明确结束；认证明确被平台拒绝时立即停止，已经连接成功后断线仍需手动重连。

设置页增加尝试次数、主机 / 端口及连接诊断；错误只记录归一化原因，不记录 Cookie、直播 token 或原始请求。旧连接的迟到事件不能覆盖新连接，断开 / 注销会终止剩余尝试。

应用版本更新到 v0.1.1，插件继续为 0.3.0，此修复无需重新导入插件。32 项应用测试通过，包含新增的连接停滞、443 回退、所有候选超时、HTTP 拒绝、认证拒绝及迟到事件测试；已在用户报告的真实房间以独立游客会话确认「2245 超时 → 443 → 直播认证成功」。该记录证明连接及认证恢复，不替代登录账号点歌入队的人工验收。

更新当前开发服务后，亦观察到用户账号模式经相同回退完成直播认证并收到弹幕；修订 ZIP 的独立解压检查通过。此前登录凭据未被导出或写入交付包。

免安装包名称为 `SPlayer-Live-Player-v0.1.1-win-x64.zip`。下文保留 v0.1.0 的首版基线及通用构建流程。

## 构建

在 Windows x64、Node.js ≥ 22.12 环境中使用根目录锁文件安装依赖，执行：

```sh
npm ci
npm test
npm run release
npm run release:check
```

`npm run build` 仍仅构建可导入的单文件插件。`npm run release` 先构建插件，再将正式后端及其依赖打包，复制网页、共享浏览器模块、当前 Node 运行环境、第三方许可和中文使用说明，生成 `release/SPlayer-Live-Player-v0.1.0-win-x64.zip` 及同名 `.sha256` 文件。

为避免覆盖已有交付物，重复构建会增加 `-2`、`-3` 后缀。`release:check` 默认检查最新生成的 ZIP，也可以指定文件：

```sh
npm run release:check -- release/SPlayer-Live-Player-v0.1.0-win-x64.zip
```

首个包内置 Node.js v24.21.0 x64，运行时许可保留在 `runtime/LICENSE`。构建只使用本地已经安装并锁定的依赖，不在构建时下载运行环境。开发工具、独立实验、参考仓库、工作区的 `*.local` 配置及账号数据不进入交付包。每个包包含版本信息、文件清单与 SHA256；校验值用于发现损坏，不作为发布者签名。

## 使用

将完整 ZIP 解压到可写文件夹，双击 `启动歌词设置.cmd`，启动器打开本地设置页。无需另外安装 Node.js 或 npm。保留服务窗口，Ctrl+C 停止本次服务。

在 SPlayer-Next 本地导入 `plugins/splayer-live-lyrics.js`。歌词需要 API 4 或以上，点歌和原生队列需要 API 5。设置页为 `http://127.0.0.1:19633/`，OBS 输出为 `http://127.0.0.1:19633/obs`。

如果默认端口已有本项目的服务，启动器打开已有实例，既不接管也不关闭它；如果是其他服务则明确报错。切换到新版本前需要先停止旧实例。当前开发目录中的服务继续运行不会因构建而重启。

自定义 CSS 和布局保存在所解压文件夹的 `*.local` 文件中。升级时先停止旧服务，可手动复制这两项配置。B 站登录凭据及待处理点歌仅存内存，重启后重新登录、连接并启用；原生播放列表继续由 SPlayer 管理。

## v0.1.0 范围

- 透明歌词输出，向上淡出 / 向下淡入，音译和翻译副行，长行滚动及宽度适配。
- 圆形旋转封面、歌名和歌手，以及切歌和首尾留白过渡。

- B 站二维码 / Cookie 登录、账号 / 独立游客连接、弹幕及身份状态。
- 账号模式下的明确点歌指令、搜索首项追加原生队尾、真实队列显示和有上限的待处理记录。
- 不确定入队不重放，显示核对提示；歌词与点歌任务独立运行。

AMLL 及其他额外渲染器、安装程序、托盘、自动更新、账号持久化和其他系统架构不在此包范围内。此首版仍按本机使用设计。
