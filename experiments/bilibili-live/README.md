# B 站登录与直播弹幕最小验证程序

独立网页与本地 Node 后端，用于人工验收二维码登录、账号校验、直播认证及弹幕发送者信息。
页面和接入代码已实现，本地自动化及模拟平台的浏览器流程已通过；真实登录和直播弹幕结果等待用户验收。
此程序不连接点歌实验后端，不调用 SPlayer，不会因收到「点歌 xxx」而播放音乐。

## 启动

要求 Node.js 22.12 或以上，开发机使用 Node.js 24.21.0。

```powershell
cd E:\Zero_Work_Folder\Project\1.Fun_Project\SPlayer-Live-Player\experiments\bilibili-live
npm ci
npm start
```

打开 <http://127.0.0.1:19631>。仅监听本机，首次打开不会自动申请二维码或连接直播间。
端口与点歌实验的 `19630` 分开；如被占用，可先设置 `$env:BILI_DEMO_PORT = '19632'` 再启动。
在前台运行的终端按 `Ctrl+C` 停止；关闭浏览器标签页不会停止后端或直播连接，需先点击“断开连接”。

本次开发已在后台启动默认端口。若需要停止这次后台实例，可先用下列命令查看占用进程，并核对它确为本实验的 Node 进程，再执行 `Stop-Process -Id <进程号>`。

```powershell
Get-NetTCPConnection -LocalPort 19631 -State Listen | Select-Object OwningProcess
```

## 人工验收步骤

1. 点击“二维码登录”，用哔哩哔哩手机客户端扫码并确认；观察等待扫码、等待确认及账号校验状态。二维码过期时重新点击，也可以取消本次登录。
2. 页面出现接收账号昵称、UID 和“登录有效”，再点“检查登录状态”确认。若二维码路径不可用，可展开手动 Cookie 导入作为备选。
3. 输入目标直播间号，点击“连接直播间”。检查真实房间号、开播状态，以及 WSS 建立后的认证结果；只有收到认证成功回复才显示“认证成功”。
4. 在 B 站网页或客户端向该直播间发送“歌词验收”。页面应显示接收时间、发送者昵称、发送者 UID、身份状态及完整文本，含“歌词验收”的行会高亮。
5. 建议使用另一个账号发送，确认发送者 UID 与登录接收账号分别记录。身份缺失或受限的消息应明确标记，不能统一当作 UID 为 0 的一个用户。
6. 刷新页面，应恢复当前账号、连接状态及最近消息；点击“断开连接”后不再接收新消息。切换账号或移除本地登录态会断开旧连接并清空弹幕列表。
7. 点击“导出验收记录”保存 JSON。它包含账号、房间、阶段记录和最近弹幕，排除二维码图像、Cookie、扫码密钥与直播 token，可用于记录实际结果。

| 验收项 | 通过证据 | 当前结果 |
| --- | --- | --- |
| 真实账号登录 | 扫码后账号 UID／昵称正确，主动检查仍有效 | 待用户验收 |
| 真实直播认证 | 正确真实房间号及认证成功回复 | 待用户验收 |
| 真实弹幕接收 | 实际发送文本与页面对应，能区分发送者和接收账号 | 待用户验收 |
| 异常与恢复 | 过期、错误房间、断开、重新连接及身份缺失表现清楚 | 待用户验收 |

## 行为与限制

- 登录态只在后端内存中保存，重启后重新扫码／导入；不写凭据文件，不做自动 Cookie 刷新或账号持久化。
- 二维码生成和轮询由后端执行，Cookie jar 处理 `Set-Cookie`；登录账号以 `nav` 校验结果为准。二维码完成本身不代表直播认证通过。
- 直播连接包含短号解析、设备标识、WBI 签名、同接收账号 UID 认证，以及心跳维护。额外向认证包传递同会话的 `buvid`，兼容性仍待真实服务验收。
- 支持普通包、合包、zlib／Brotli 压缩和嵌套包；最多保留最近 100 条弹幕及 40 条阶段记录，并限制单帧及解压大小。
- 先使用返回的第一个有效 WSS 节点。连接失败、断开或心跳超时后显示阶段错误，由用户手动重连；当前没有自动重连、节点轮换、消息去重或生产环境调度。
- UID 缺失、神秘用户或两组 UID 冲突会标记身份缺失／受限；登录不能保证每条消息的身份资料都完整。昵称只用于显示。
- 不发送弹幕，不处理礼物等业务事件，不把弹幕转发给点歌链路。导出的记录含用户标识和弹幕内容，由验收人员自行保留。
- 设置页通过同源接口与 SSE 接收状态，操作请求需本地管理令牌。没有外部网页脚本或二维码图片服务依赖。

## 本地验证

```powershell
npm test
```

11 项自动化测试使用模拟平台 HTTP 响应和 WebSocket，并通过真实本机 HTTP 验证页面、管理令牌、同源限制及 SSE。
覆盖 WBI 固定向量、压缩嵌套包、扫码状态、取消后的迟到响应、Cookie 导入、网络失败与失效、同 UID 认证、心跳、发送者身份和断开时的在途请求。

另用无头 Chrome 完成模拟平台的完整网页流程：扫码状态、账号检查、连接、压缩弹幕、文本安全显示、导出、页面刷新、断开与本地退出；检查桌面及窄屏布局。
浏览器检查工具和截图放在忽略的 `tmp/`、`logs/`，不属于运行依赖。这些结果均不替代上表的真实平台验收。
